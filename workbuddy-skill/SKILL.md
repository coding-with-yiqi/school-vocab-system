# 背单词闯关发布台

给中学老师用。老师不维护词句库，不自己检查，不搭服务器。

## 这个 skill 替老师做什么

```
课本词表 / 备课资料          ← 老师已有，不用重新录
        │
   build_pack.py             ← 纯模板填充，不调大模型，不耗 token
        ▼
   背课包 pack.json           ← 5 个关卡自动排好
        │
   publish.py                ← 注入网页模板
        ▼
   一个单文件 HTML            ← 27 KB，手机打开就玩，断网也能继续
        │
   发到家长群
        ▼
   学生在家做完，点「交作业」
        │
   飞书多维表格               ← 成绩自动进表，Dashboard 自动更新
        ▼
   学生页「我的复习」          ← 学生点开时按班级+姓名去后端现查，没背下来的词只给他自己
```

老师在这中间只说两句话：「这周学 Unit 3」和「收一下作业」。命令全由你跑。

## 老师不碰命令行

老师只跟你说话。下面每一句话，你替她跑**一条** `scripts/beike.py`，
把它的输出用大白话转述给她。不要把命令贴给她，不要让她自己跑任何东西。

她的名单、表单链接、学生链接、错题池都记在她电脑的 `~/.beike/` 里，
说过一次就记住了 —— **不要每次再问她要名单。**

### 发新单元时，词表从哪来

按这个顺序找，找到就停：

1. 她这次直接给的文件、照片、粘贴的文字；
2. WorkBuddy 项目里本单元的备课资料；
3. 她的教学进度表里当前课次对应的单元。

找不到就问她要：课文、课本后面的单元词汇表、备课 Word、课件、PDF、拍照，给什么都行，**不要自己编单词**。
拿到以后按下一节转成词表。

### 拿到一课的资料，怎么转成词表

她给的东西不用她先整理。你来转，按这几步，一步都别跳。

**范围和数量由她定，不由你定。**
- 她给一篇课文，就只做这篇课文；给一个单元，就做一个单元；给一页词汇表，就做这一页。
- 她说了考哪些、考几个，就照她的。
- 她没说，就把资料里的全放进去。查完告诉她一共多少题、大概几分钟，她嫌多再删。
- 词表里放了多少，网页就考多少。

1. **抽文字。** `python3 scripts/wordlist.py 抽 <文件> <文件> -o 原文.txt`
   - Word / 课件 / PDF / txt 都能抽，几个文件一起给。
   - 照片和扫描版 PDF 抽不了，脚本会提示。你直接看图，把词汇表和课文抄进原文。
2. **写 `## 词`。** 词只能来自她给的资料：
   - 资料里有词汇表（Words and Expressions），或者她标了「重点」的，就用这些；
   - 只有一篇课文，就挑这篇课文里的生词和短语。
   - 每行「英文 | 中文」。中文照资料抄；资料里没有中文，就写**这篇课文里的意思**，别写词典第一义。
   - 左边写学生要拼出来的样子，去掉 sb / sth / 省略号 / 斜杠 / 括号 / 词性：
     `devote oneself to sth. v. 致力于` → `devote oneself to | 致力于`。
   - 标题写清范围，学生和成绩表里都看得到这个名字。比如 `# Unit 3 Reading 课文`、`# Unit 3 词汇表 第 1 页`。
3. **写 `## 句`。**
   - 从课文里挑含有这些词的原句，最好每个词一句，每句不超过 25 个词。课本原句直接用。
   - 她给了作文要背的句子，这些优先放进来。
   - 右边写中文：资料里有就抄，没有就你来翻译。
4. **写 `## 错`。**
   - 她给了错题，就用她的错题。
   - 没给，你可以照着 `## 句` 里的句子写 3–5 个学生常犯的错句。
   - 第三列错因只能写：时态 / 词性 / 搭配 / 拼写。
5. **查。** `python3 scripts/wordlist.py 查 词表.md`
   - 有「错误」就改，改完再查，一直查到出现「通过」。
   - 「提醒」看一眼，能改就改。
6. **存一份。** 把词表存到 `~/.beike/词表/<标题>.md`，下次她说「再发一次」直接用。
7. **告诉她一句，等她点头再发。** 比如：
   「Unit 3 Reading 课文：词 15 个、句 6 个、错句 4 个（错句是我照课文写的），学生大概做 12 分钟。要删一些吗？」
   她说行，就跑 `beike.py 发 <词表.md>`。她说想先看看，就加 `--只生成`。
   - 上次全班没背下来的词，发的时候会自动排到最前面。这次词表里没有的，会从以前发过的包里补进来，最多 5 个。
     发完的输出里会列出补进来的是哪几个，把这一行也告诉她。

她想换剧情时，按「剧情怎么换」写一个 json，加 `--剧情 x.json`。
她想先看看不发，加 `--只生成`，把网页文件给她看。

### 几件你要替她记着的事

- **链接一学期不变。** 每次「发」都更新同一个飞书应用，班群里置顶那条点开就是最新单元。
  她问「要不要重新发链接」—— 不用，发一句「新单元上了」就行。
- **名单没有就先要名单。** `发` 会拒绝没有名单的情况：学生自己打班级和姓名，
  她会收到「高一3班」「高一（3）班」「1703」四种写法和错别字，清洗比她手工检查还累。
- **几个班共用一个链接。** 学生选自己的名字，班级跟着走。两个班都有「王小明」不会串。
- **旧课一直都在。** 一学期的课都在同一个网页里分页放着，学生没背会可以回去接着做、接着交，成绩记在那一课名下。
- **复习自动滚，她能改。** `收`（和 `看`）完会起草 `~/.beike/复习计划.json`：每个学生哪些词还没拿下（某个词连续两次第一遍就对才算拿下，「用时偏短」的那次不算），全班这一课错得最多的前 10 个词。`发` 不再拿它往新课里塞复习词（不传 `--review`，错题池那条也停了）；全班最卡的前 10 只进看板和学情摘要。她要改就用 `复习` 命令，不用确认。
- **「我的复习」现查（`~/.beike/config.json` 里有 `review_api` 时）**：网页里不放任何人的单子，学生点开「我的复习」时，页面拿班级 + 姓名去问后端（`04_工程/review-api/`），后端是妙搭全栈应用「背单词闯关口语」（<你的应用 id>）的 `GET /student-api/review`（公开、不用登录），飞书的成绩、单元、词表、复习设置四张表用妙搭「Base 数据同步」实时同步进它自己的库（成绩只同步算复习要的列，不同步分数），按 learning.py 同一套规则现算，只回词和中文。查不到时学生只看到「你的复习单暂时打不开，先做本课」，不拿全班的词顶替。去掉 / 加上由后端读「复习设置」表，关掉＝下一次发的学生页没有这一格。真「发」时会把每一课的单元行、词表行（含题号、变形两列）写进飞书，给后端用；`--只生成` 不写。后端 2026-11-17 已上线，细节见 `04_工程/review-api/README.md`。
- **没配 `review_api` 时，「我的复习」里的词是发的时候写进网页的**，不会实时更新：学生在两次「发」之间背会的词，要等下次发才从他的「我的复习」里消失。网页源码里每个人的词按名单位置存，不写名字，但拿着名单能对上，别当成保密的东西。
- 学生链接是 https://<你的租户>.feishuapp.com/app/<你的应用 id>/student-api/page（妙搭全栈应用直接给整页，不在 iframe 里，没有「登录」按钮）。旧的飞书「page」链接是 html 应用，「我的复习」和交作业在里面都不通，别再发。
- `~/.beike/apps.json` 记着飞书应用的编号，**不能删**，删了链接就变了。
- `发` 报「设公开没生效」：多半是她学校的飞书管理员关了对外分享，告诉她找管理员，你绕不过去。

### 第一次用之前，要她做一次的

1. 本机装好 lark-cli 并登录她自己的飞书（`lark-cli auth login`）。这一步要她扫码，你没法替她。
2. 给你三个班的名单。
3. 跑一次 `beike.py 建表`。成绩表和交作业表单你替她建，她不用打开多维表格。
4. 装 wechat-cli（备用路线要用）：照 `wechat-cli-readonly-skill` 装。要点：
   macOS 上 `npm install -g @canghe_ai/wechat-cli`，然后**她自己**在终端跑一次 `sudo wechat-cli init`（要输开机密码，你不能替她输），
   终端要有「完全磁盘访问权限」，微信要是 skill 里写的那个版本、并且开着登录。
   `beike.py 状态` 里能看到装没装。没装也不影响主路线，`收` 会提示一句然后照常从表里报。
   wechat-cli 只读：不发消息；`~/.wechat-cli/` 里的密钥文件不要打开、上传或发给任何人；只取 `BK2|` 结果码，聊天别的内容不看不存。

### 底下这几个脚本是干什么的

`beike.py` 只是把下面几个串起来，一般用不到单独跑：

- `wordlist.py` 一课的资料 → 词表：`抽` 把 Word / 课件 / PDF 里的文字抽出来；`查` 检查词表能不能直接发。
- `build_pack.py` 词表 → 背课包（5 个关卡），纯模板，不调大模型。
- `publish.py` 背课包 + 名单 + 表单 → 一个单文件网页。模板在 `assets/student.html`。`--book ~/.beike/课` 把整个课目录做成一个网页（`发` 用这个）；超过 15 课，更早的课去掉剧情文字，题都留着。
- `units.py` 课目录：`~/.beike/课/目录.json` + 每课一个文件夹。第几课一旦分配就不变。
- `learning.py` 每次从成绩表 + 课目录从头算：每个学生每个词的状态（还不会 / 差一点 / 拿下）、错在哪几课、连续对几次，和全班前 10。自己核对：`python3 learning.py 结果码.txt --谁 高一3班·林小雨`。
- 上线：config 里有 `page_app` / `page_url` 时，`beike.py` 把网页插进全栈应用库的 `student_page` 表，学生链接读最新一行（两三秒）；没有时才用 `deploy.py` 发成 html 应用（旧路）。
- `collect.py` 结果码 → 成绩表 + 谁没交 + 错题池。`收` 先把群里抓到的结果码写进多维表格（按 班级+姓名+单元+第几次 去重），
  再把表里每一行还原成结果码交给它，所以两条路交的作业都在一张表里。

### 看板怎么算的（她问「这个数怎么来的」时照这个答）

- 数据只从飞书拉：成绩表（必须有），名单 / 单元 / 词表 三张表有就用。没有名单表就用本机 `名单.txt`；两个都没有，只能说谁交了，**算不出谁没交**，页面会直接写出来。
- 易错词只算每个人**第一次**提交；每个学生的四个数看**最近一次**；「用时偏短」看每一次。
- 四个数加起来不等于题数的提交，页面顶上会单独列出来。
- 「复习拿下了多少」统一用 learning.py 的口径（连续两次第一遍就对 = 拿下）：看板、摘要、宠物都用它。旧的「下一课词表里标了复习」那套算法（recovery）新规则下一定是 0，看板不再显示；`archive.py` 收尾摘要里还在用，归 beike-archive 改。
- 「家长确认」「听写」两块是占位，写着「还没上线」，没有数据。听写以后按 对了/差一点/还不会 算进那四个数，不加新字段。
- 页面是快照，不会自己更新，也不连任何网站；里面没有飞书凭证。

### 宠物怎么算的（她或学生问「为什么我的还没孵」「我还能拿几颗」时照这个答）

- 每个单元单独算，看最近一次提交：交了 +2；按对的题数，最多 +6（对了 ÷ 不算造句的题数 × 6）；重做后「对了」变多 +2；造句写了 +1；全班这单元交到九成，每人 +2（看最近一个有人交的课）。期末课按每个人自己的题数算。「我的复习」每交一轮 +2；错过的词拿下了（连续两次第一遍就对），每个 +1。老师送东西 +3。「用时偏短」的那次不算豆子。一个单元满打满算 18 颗左右。
- 长大看「一共挣了多少」：8 颗孵出来，30 颗长成少年，80 颗长成完全体。没交不扣豆子，宠物不会走。
- 能花的豆子 = 挣的 − 换配饰花掉的。花掉的不影响长大，所以换配饰不会让宠物变小。
- 小卖部：头上 8 颗、手里 6 颗、身边 10 颗；每单元新上架的贵 2 颗。蛋孵出来以后才能换。每个位置戴一件，学生自己选。
- 每张卡片下面写着「这单元还能拿几颗」：没交的是「交了最多还能拿约 9 颗」，交了没满的是「再做一次、对得更多，还能拿 N 颗」。
- 全班场景：全班人均挣到 15 / 40 / 80 颗，解锁草地 / 温泉 / 星空，全班的宠物一起换背景。宠物墙上写着「全班一起再挣 N 颗就到了」。
- 孵出来是 11 种小动物里的哪一种（卡皮巴拉、羊驼、猫、柴犬、小黄鸭、兔子、仓鼠、熊猫、企鹅、水獭、小狐狸）由班级 + 姓名 + 学期决定，开学就定了，没有稀有度。宠物墙按名单顺序排，不排名。
- 每次都从成绩表从头算。手写的只有 `~/.beike/宠物/` 下的 `送的.json`（老师送的）、`换的.json`（学生换的）、`穿戴.json`（戴哪件）、`装备.json`（老师指定的单元配饰）。这四个文件在飞书「宠物账本」表里有备份（见上面的表）。账本里改了不会回到本机，以本机为准；她要改记录，用换 / 退 / 送 命令，别直接改表。

### 两条交作业的路

- **主路线：表单。** 学生做完点「交作业」，页面在飞书框里跳到表单。所有题都用 `hide_` 藏起来了、成绩用 `prefill_` 带过去，
  学生看到的只有一个「提交」按钮，**什么都不用填，也填不错**。
  实测过：飞书外壳的 iframe 不允许弹新窗口、也不允许跳整页，只能在框里跳 —— 网页就是这么做的，别改成 `window.open`。
  为什么不在网页里直接写表：写多维表格要凭证，网页是公开的静态文件，放进去谁都能拿去乱写。表单是飞书给的「免凭证写一行」的口子。
- **备用：结果码。** 表单打不开时，学生复制一串 `BK2|…` 发班群。她说「收一下作业」，你用 wechat-cli 去群里抓、写进表。
- 数据流图：见仓库 README.md 的「架构」一节。

## 词表格式

老师直接从课本词表粘，一行一个，`|` 分隔。只有「## 词」是必需的。

```markdown
# Unit 1 People of Achievement
## 词
achievement | 成就；功绩
devote | 致力于；献身于
## 句
He devoted his whole life to the cause. | 他把一生都奉献给了这项事业。
## 错
He devote his life to science. | He devoted his life to science. | 时态
```

- `## 词` → 闪认关 + 自动生成的填空关干扰项 + 造句关的必用词
- `## 句` → 默写关；句子里出现了词表里的词，还会自动挖空做成情境填空关
- `## 错` → 改错关；第三列是错因（时态／词性／搭配／拼写），学生改对了还得说清为什么错

没有 `## 句` 和 `## 错` 也能跑，只是关卡少几个。

## 剧情怎么换

`--episode` 指一个 json，5 幕，学生每过一关解锁下一幕。默认是占位文案。

换成班上学生在追的剧最有效：把剧情梗概写成 5 段，每段结尾留个钩子。也可以直接用课文本身的情境（`示例剧情_一株青蒿.json` 就是 Unit 1 课文改的）。

```json
{ "title": "剧名", "tagline": "一句话钩子",
  "scenes": [{ "id":"S1", "label":"第 1 幕", "time":"00:00–01:30",
               "text":"这一幕讲什么", "cliff":"先过这一关，下一幕解锁。" }] }
```

## 边界

- **不编单词。** 词必须来自课本或老师的备课资料。找不到就问，不要生成。中文释义、句子翻译、错句可以由你来写，但要告诉她哪些是你写的。
- **造句题不判对错。** 系统只检查有没有用上指定的词、够不够长，然后标成「需老师看」。靠不靠谱由老师判断。
- **文字背对了不等于会说。** 网页上的结果是练习参考，不是成绩。
- **网页里不放密钥。** 学生端是纯静态单文件，飞书的 app secret 只留在老师本机，由 lark-cli 管。
- 没给名单时学生自己填名字，可能写错或重名。所以名单别省。
