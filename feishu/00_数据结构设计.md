# 数据结构：从老师真实要回答的问题反推

不先画表。先问老师每天、每周、期末分别要回答什么问题，
问题定下来，字段就只剩一种合理的长法。

---

## 一、她真正要回答的问题

### 今晚和明天早读前（每天都要）
| 问题 | 要什么数据 |
|---|---|
| 谁没交 | **全班名单** 减去 今天的提交 |
| 谁交了但一塌糊涂 | 今天提交里「还不会」多的 |
| 明天课上该重讲哪几个 | 今天全班没拿下的词排行 |
| 谁的造句我得亲自看 | 造句原文 + 提交人 |

**「谁没交」是她每天最花时间的事。** 而没交的人在提交记录里根本不存在 ——
这一条决定了必须有一张学生名单表。不是为了规范，是为了催作业。

### 一个单元结束后（每周）
| 问题 | 要什么数据 |
|---|---|
| 这个单元全班塌在哪 | 按内容包聚合的错题排行 |
| 谁一直在欠账 | 跨单元的提交率 |
| 第二次做有没有进步 | 同一个人同一个包，第一次 vs 最后一次 |

### 期末前（一学期一次）
| 问题 | 要什么 |
|---|---|
| 每个学生还差哪些 | 一人一份专属错题单 |
| 全班集体过一遍什么 | 整学期 TOP 30 |
| 要给年级组交的落实情况 | 提交率 × 首次通过率 |

### 随时（家长问起）
「我家孩子最近英语怎么样」→ 一个学生跨单元的轨迹。

## 二、六个关键判断

这些是真实需求和工程直觉打架的地方，先说结论。

### 1. 班级不能让学生打字

一个班发一个链接，班级**烧死在链接里**（`?c=高一3班`）。
姓名也不让学生打 —— 那个班的名单烧进网页，**学生从下拉里选自己**。

> 让学生自己填，你会同时收到「高一3班」「高一（3）班」「1703」「三班」，
> 以及「王小明」「王小朋」「小明」。清洗这些数据的时间比她手工检查作业还长。

她发 3 个链接到 3 个班群。班级零歧义，姓名零错字，学生还少打字。

### 2. 多次尝试要全留，但「通过数」会骗人

学生可以反复刷到全对。所以单看通过数等于没看。要三个数一起：

| 数 | 说明什么 |
|---|---|
| **第一次**的对题数 | 真实掌握程度 —— 这才是她该看的那个数 |
| **最后一次**的对题数 | 最终有没有搞定 |
| **尝试次数** | 花了多少劲（或者在刷） |

第一次 10/14 → 第三次 14/14，这是**好事**，该表扬。
第一次就 14/14，那是真会。两种人现在在表里长得一样，必须分开。

所以提交记录是 **append-only**：一次提交一行，永不覆盖。
「每人每包最新一次」是一个**视图**，不是一张表。

### 3. 「对了」要拆成四个数

现在的字段是 `通过数 / 接近数 / 未通过数`，有两个坑：
造句（系统不判对错）被算进了通过数，「差一点」被塞进了「未通过清单」。
改成四个互不重叠的数，**加起来等于题数**：

```
对了 ＋ 差一点 ＋ 还不会 ＋ 待老师看 ＝ 题数
```

老师一眼能验算，也就一眼能信。

### 4. 要防「抄的」和「刷的」

高中生会互相抄，也会无脑点到全对。她最怕的不是数据难看，是数据是假的。
学生端已经记了用时，加一个判断就够：

> 用时 < 题数 × 8 秒 且 对题率 > 90% → 标记「用时偏短」

**只提示，不判定。** 她自己看一眼就知道那个孩子什么情况。

### 5. 期末总结不是一张表，是一个生成动作

她期末前真正想做的事，不是看统计，是**给每个学生发一份「你这学期一直没拿下的 20 个词」**，
让他针对性背。那是一个网页，不是一行记录。

```
build_pack.py --student 王小明 --term 2026秋   →  王小明的期末冲刺包.html
```

飞书只要能把数据给出来就够了。别为了期末专门建一张「总结表」，
那张表她看一次就再不打开。

### 6. 别在飞书里做关系运算

「名单减提交算出谁没交」是一个左连接。飞书多维表格做不了，
硬做要配双向关联 + 统计字段，而表单提交的文本「王小明」不会自动变成关联记录。

分工定死：

> **飞书负责存，和给她翻。算账在本机脚本里做。**

她跑一条「收作业」，脚本直接打印：
`高一3班 42 人，交了 35，没交：张三、李四……`
这比在多维表格里折腾公式靠谱一百倍，而且她本来就要跑这条命令。

## 三、四张表

```
学生名单 ──┐
           ├─▶ 本机脚本 ──▶ 错题榜（给看板画图）
提交记录 ──┤                      │
           │                      └──▶ 下个背课包 / 个人期末包
内容包   ──┘
```

### 表 1「学生名单」— 她一学期只动一次
| 字段 | 类型 | 谁填 |
|---|---|---|
| 姓名 | 文本 | 她从班级 Excel 粘进来 |
| 班级 | 单选 | 同上 |
| 学号 | 文本 | 同上，只用来区分重名 |
| 在读 | 复选，默认勾上 | 转班、休学时取消 |

开学粘一次，10 分钟。之后整学期不动。
**「零维护」指的是每次布置作业零维护，不是一辈子零录入。**

### 表 2「提交记录」— 学生表单直接写，只增不改
| 字段 | 类型 | 来源 |
|---|---|---|
| 提交时间 | 创建时间 | 飞书自动 |
| 班级 | 文本 | 链接预填 |
| 姓名 | 文本 | 页面下拉选 |
| 内容包 | 文本 | 预填 |
| 第几次 | 数字 | 预填（学生端自己数） |
| 对了 | 数字 | 预填 |
| 差一点 | 数字 | 预填 |
| 还不会 | 数字 | 预填 |
| 待老师看 | 数字 | 预填 |
| 还不会清单 | 文本 | 预填，`、` 分隔 |
| 差一点清单 | 文本 | 预填 |
| 造句原文 | 文本 | 预填 |
| 自评 | 单选 | 预填 |
| 用时秒 | 数字 | 预填 |
| 用时偏短 | 复选 | 预填 |
| 明细 | 文本 | 预填，逐题判定，出问题时查账用 |

### 表 3「内容包」— 发布时脚本自动写一行
| 字段 | 说明 |
|---|---|
| 内容包 | 主键，如 `RJ-XB1-U3-20261118` |
| 册次单元 | 人话，如「必修一 Unit 3」—— 她的心智是这个，不是 ID |
| 题数 | 用来验算四个数加起来对不对 |
| 发布日期 | 日期 |
| 面向班级 | 多选 |
| 是否复习包 | 复选 —— 复习包的成绩不能跟首次混在一起算 |

### 表 4「错题榜」— 老师跑「收作业」时脚本写入
| 字段 | 说明 |
|---|---|
| 班级 / 内容包 / 词或题 | 三者定位一行 |
| 类型 | 单词 / 句子 / 改错 |
| 还不会人数 / 差一点人数 | 数字 |
| 没拿下人数 | 两者之和，看板按这个排序 |
| 更新时间 | 日期 |

**为什么要单独一张表：** 「还不会清单」是一个用 `、` 分隔的文本字段，
飞书图表不会把它拆开，所以直接拿提交记录画「易错 TOP」是画不出来的。
聚合成一行一个词，看板一个条形图就搞定。

行数也可控：3 个班 × 10 个单元 × 50 词 ≈ 1500 行。
（**顺带一个要你自己确认的事**：飞书多维表格单表行数上限按版本不同差很多，
免费版的说法低到几千行。按这个结构，提交记录一学期约 3000 行，
错题榜约 1500 行，都在安全范围。但别做「一行一个学生一个错词」那种展开，
那是 15000 行起，一学期就顶到天花板。）

## 四、视图

**提交记录上建：**
| 视图 | 筛选 | 她什么时候看 |
|---|---|---|
| 今天交了谁 | 提交时间=今天，按班级分组 | 每天晚自习前 |
| 要我亲自看的 | 待老师看>0 **或** 自评=我还不会 **或** 还不会≥5 **或** 用时偏短 | 每天，唯一必须逐条读的地方 |
| 每人最新一次 | 按 姓名+内容包 分组，取最新 | 单元结束时 |
| 首次成绩 | 第几次=1 | 看真实掌握，不被刷分污染 |

**错题榜上建：** 按班级分组，没拿下人数降序。明天课上讲什么，看这一屏。

**学生名单上：** 不建视图。「谁没交」由脚本算，不在飞书里凑。

## 五、看板

| 图 | 类型 | 数据来自 | 回答 |
|---|---|---|---|
| 今日提交人数 | 指标卡 | 提交记录 | 多少人做了 |
| 各班提交率 | 条形图 | 提交记录按班级 | 哪个班要催 |
| 首次对题率分布 | 直方图 | 提交记录，第几次=1 | 班级整体什么水平 |
| 易错 TOP 20 | 条形图 | **错题榜** | 明天讲什么 |
| 自评 vs 实际 | 散点 | 提交记录 | 谁虚、谁其实会但不自信 |

最后一张图是她最该看的：自评「我会了」但还不会数高的那几个，
是班里最危险的学生 —— 他们自己不知道自己不会。

---

## 六、边界

- 文字背对了 ≠ 会开口说。整套系统**完全没有口语**这一维，期末评价别拿它当全部。
- 造句永远人工看，系统不冒充老师。
- 「用时偏短」是提示，不是指控。
- 这张表是落实度，不是成绩。写进任何正式评价之前先想清楚。
